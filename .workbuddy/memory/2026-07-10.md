## poster.html 性能诊断

完成 poster.html 页面加载性能八维度系统性诊断，生成 HTML 报告 `poster-perf-diagnosis.html`。

**P0 根因（3 项）**：
1. `/api/poster` 同步串行调用 ffprobe × N，30 视频阻塞 ~5s（main.py:1493）
2. 缩略图接口 FileResponse 直传未压缩原图，无 resize/WebP（main.py:1529）
3. 所有 FileResponse 无 Cache-Control 头，每次刷新全量重载

**P1（3 项）**：toggleSelect 全量重渲染、客户端重复时长探测、CSS 全站未拆分未内联关键路径

**P2（2 项）**：无 gzip、innerHTML 字符串拼接

预期：P0 修复后首次加载 6.5s→1.2s，缓存命中 0.35s。

## 按 P0→P1→P2 顺序实施全部优化

### P0-1: ffprobe 异步化
- `_collect_poster_items` 不再同步调用 `_probe_video_duration`
- 新增 `_duration_cache_lock` 线程锁 + `DURATION_CACHE_PATH` 持久化 JSON 缓存
- 新增 `_batch_probe_durations()` 使用 `ThreadPoolExecutor(max_workers=4)` 后台并行探测
- 新增 `/api/poster-durations` 端点供前端轮询补充时长
- `_invalidate_poster_cache()` 同时清除持久化缓存文件

### P0-2: 缩略图动态压缩
- 安装 Pillow 依赖
- 新增 `THUMB_CACHE_DIR` 磁盘缓存 + `_get_or_create_thumb()` 函数
- `api_thumb` 改为生成 320×180 WebP (quality=80)，并添加 Cache-Control 头
- 缓存键基于 st_mtime_ns + 路径 md5 哈希，源文件变更自动重建

### P0-3: 缓存策略
- 新增 `add_cache_headers` 中间件：/static/ 永久缓存，缩略图 86400s，视频 3600s
- 新增 GZipMiddleware（minimum_size=500）

### P1 前端优化
- **toggleSelect 局部 DOM 更新**：使用 `data-key` 属性 + `classList.toggle()`，不再全量 renderGrid
- **移除客户端 video 要素探测**：删除 `scheduleDP()`/`runDP()`，改为轮询 `/api/poster-durations`（首次 2s、5s、12s 三次）
- **关键 CSS 内联**：reset + shell + hero + skeleton 约 30 行内联，完整 CSS 通过 `preload` + `onload` 异步加载
- **资源预加载提示**：`preconnect /api`

### P2 额外优化
- **SVG Sprite**：icon-chevron/icon-close/icon-play 定义为 `<symbol>`，卡片中通过 `<use>` 引用
- **DocumentFragment**：renderGrid 改用 `createCardElement()` + `createDocumentFragment()` 增量构建 DOM
- `.gitignore` 添加 `.thumb_cache/` 和 `.duration_cache.json`

### 文件变更
- `main.py`：ffprobe 异步化、缩略图压缩、缓存头、GZip
- `templates/poster.html`：全面重写 JS 交互 + CSS 内联 + SVG sprite
- `.gitignore`：运行时缓存忽略
